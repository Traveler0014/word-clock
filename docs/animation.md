# 灯板动效设计（草案 · 2026-10）

> 状态：**参数在网页实验台里调，未落到固件**。本文是设计规格，实验台
> [`tools/anim_lab.html`](../tools/anim_lab.html) 是它的可执行版本。

## 为什么需要一套"语法"

114 颗 RGB 灯能做的东西无限多，但**克制**才是这个产品的调性（面板是黑色镂空字母，
网页端也是纯黑白 + 衬线）。所以先立六条硬规则，任何效果必须满足：

| # | 规则 | 参考值 | 违反之后 |
|---|---|---|---|
| 1 | 周期 ≥ 3s 且互不整除 | 3.6 / 4.7 / 6.1 / 8.3s | 显出"机器在循环" |
| 2 | 同屏活跃 ≤ 1/3 | ≤ 36 颗 | 像屏幕坏了 |
| 3 | 峰值压低，且**分级** | 氛围 8–20，状态 30–70（码值） | 超过 90 就变成"通知" |
| 4 | 不同步 | 每颗独立相位/周期 | 齐呼吸 = 呼吸灯玩具 |
| 5 | 单一色相家族 | 近白 + 少数偏暖/偏冷 | 彩虹渐变立刻变土 |
| 6 | 永远经过 0 过渡 | 淡入淡出 ≥ 400ms | 硬切 = 廉价 |

## 物理前提：一颗灯 = 一个字母

面板是镂空字母 + 扩散板，所以"亮一颗灯"是**点亮一个字母**，不是点亮一个点。这带来
这个产品独有的一个表达维度：

> **字母的可读性本身可以当参数用**。码值 8–20 时只是肌理（读不出字），
> 40 以上开始被读成文字。星场因此可以"用同一套字母做星空"。

## α 与码值（8bit）对照

WS2812 是 8bit **线性光**输出，而人眼近对数，所以设计用「感知 alpha」，输出前过
gamma 2.2。这张表是两套语言的桥：

| α | 0.05 | 0.10 | 0.20 | 0.30 | 0.40 | 0.55 | 1.00 |
|---|---|---|---|---|---|---|---|
| 码值 | 0 | 2 | 7 | 18 | 34 | 68 | 255 |

两点后果：

1. **暗部的台阶是物理事实**。慢速淡入时码值一次跳 1，肉眼可见。所以暗部
   （码值 < 20）必须开时间抖动（2×2 有序抖动 + 帧交替）。
2. **"稍微亮一点"很贵**。α 0.3→0.55 只有 18→68，但已经是 4 倍电流。功率预算
   按码值算，不按 α 算。

## v2：一套解释器 + 两份描述符（已在实验台验证）

**结论（先回答"能否只换配置文件就得到两套主题"）：能，已验证。**
实验台现在只有一条代码路径（一个解释器 + 一组封闭生成器），两套主题就是两份
描述符；切换主题不改代码，连状态列表都不变。

### 模型

```
theme := {
  name,
  transition: { dur },                       // 状态之间的过渡（框架级，见下）
  states: { <canonical state id>: {
      stars: { overrides },                  // 星场这个"基底"怎么被调制
      mods:  [ { gen, ...params } ],         // 叠加层生成器
      text:  bool                            // 是否叠时间文字层
  } }
}
```

星场是所有状态共用的基底，状态通过 `stars` 的**乘性覆盖**来调制它：

| 覆盖项 | 作用 |
|---|---|
| `rate` | 闪烁快慢（0 = 冻结） |
| `peakMul` | 整场明暗 |
| `hue` | 整场偏暖（异常） |
| `wind` | 沿 x/y 的衰减波（只压暗，绝不点亮新格子） |
| `tide` | 极慢整体呼吸 |
| `cohere` | 相位收拢（同相脉动） |
| `gate` | 星等门槛（进度/填充） |
| `fall` | 按阅读顺序熄灭 |
| `twitch` | 停滞抽搐（每 N 秒一颗星挣扎） |

叠加层生成器（封闭集合，新增才需要改固件）：

`band`（加性光带）· `ripple`（径向涟漪）· `chase`（四角点跑）·
`ignite`（星渐现）· `fillRow`（行主序填充）· `pulse`（单格脉冲/余烬）·
`meteor`（流星）· `fadeAll`（全屏衰减）· `tick`（换词滴答）

每个生成器带 `blend`：`add` / `max` / `mul`。**混合语义由生成器定义，主题不能改**——
这条保证"星永远亮不过时间文字"这类层级约束不会被主题破坏。

### 两套主题 = 两份配置（同一状态下实测差异）

| 状态 | 星空语言 v2 | 旧母题 v1 |
|---|---|---|
| `wifi_connecting` | `stars{rate:1.2, wind{x}}` → 29 盏，峰值 0.51 | `band{period:5.5, peak:0.4}` → **101 盏，峰值 0.88** |
| `provisioning_wait` | `stars{rate:0.9, tide}` → 32 盏，峰值 0.24 | `ignite{...}` → 32 盏，峰值 0.49 |
| `error_network` | 天暗 + 暖色 + 余烬搏动 | 中心格脉冲 |
| `ota_download` | 星等门槛推进 | 行主序填充 |

v1 的"光带"会把整块面板点亮到接近白（0.88 → 码值 224），v2 的风只压暗已有的星
（峰值不超过用户设定）。同一份代码，两种审美，差异全部来自描述符——这就是把
"效果"降级成"数据"的好处。

## 光效语义框架（先定语义，再谈效果）

核心问题：**灯光要表达什么？** 面板平时只有一个职责——报时。所以任何非时间的
光形，含义必然是"我在做什么 / 我需要什么"。按此拆成五个语义通道：

| 通道 | 物理手段 | 表达 | 典型状态 |
|---|---|---|---|
| ① 存在感（情绪层） | 星场的明暗/快慢/色温 | "我在，安静" | 全部状态的底色 |
| ② 方向的进展 | 扫带（横/纵/对角）、星等门槛推进 | "正在往前走" | 连接中、OTA |
| ③ 周期性的等待 | 潮汐、四角点 chase | "轮到你了，我不急" | 等待配置 |
| ④ 一次性事件 | 流星、涟漪、滴答 | "刚才那件事成了/发生了" | 客户端连入、换词 |
| ⑤ 系统级状况 | 四角点搏动 / 亮度降级 | "有毛病，但还没死" | 网络错误 |
| ⑥ **字母点名（标签词）** | 散落选格 + 累计点亮 / 同步闪烁 | "是哪个子系统" | NET / SYNC / OTA / TIME |

### 三条硬规则

1. **亮度分级 = 注意力分级**：文字 255 > 标签 60~90 > 星场 8~20。
   用户不看内容也知道"哪里最亮 = 哪里最要紧"。
2. **一个状态最多用一个"注意通道"**（②③④⑤ 之一）+ 星场底噪。同时扫带+闪点
   会互相抢注意力，等于什么都没说。
   **但"常亮不闪的标签"不占注意通道**——它是身份/上下文，与运动叠加后语义更清楚：
   `WIFI 常亮 + 纵向快扫` = "WiFi 这一层正在逐条信道找"。同一模式也用于
   `OTA 常亮 + 斜向慢扫` = "正在写入"。
3. **语义挂在离散结构上，情绪才交给连续参数**。人隔着扩散板看一两秒，对"整体
   明暗/快慢"极不敏感，但对"哪些字母亮的、点了几颗角点"极其敏感。这解释了
   为什么纯星场主题（只调 rate/peakMul）区分不了阶段——它的语义全在连续量上。

### 两个"别做"的结论（都是本轮实测踩出来的）

**① 标签词可用，但选点必须"写死"，不能靠算法。**

两种设计意图，必须分开：

| 意图 | 做法 | 适用 |
|---|---|---|
| **一眼读出** | 描述符里写死 `cells: [[r,c], …]`，人工摆成**紧凑一簇** | 系统标签（SYNC / OTA / NET / TIME）、开屏名字（KLARA） |
| **藏一个词（彩蛋）** | 只给 `letters`，让算法把字分散到不同角落 | "让用户自己发现"的场景 |

实测跨度对比（跨度 = 行差 × 列差，越小越好认）：

| 标签 | 算法选点 | 写死点位 |
|---|---|---|
| `NET` | 6×7 | **1×3** |
| `SYNC` | 9×5 | **2×5** |
| `OTA` | 2×9 | **1×3** |
| `TIME` | 8×4 | **2×2** |

融合主题里的最终点位（均已校验拼接结果 == 目标词）：

| 词 | 点位 | 说明 |
|---|---|---|
| `KLARA` | K(9,10) → L(7,6) → A(4,1) → R(1,5) → A(0,5) | 右下 → 左上，跨度 9×9（名字本来就要铺满画布） |
| `NET` | N(2,3) E(3,6) T(2,4) | 一簇，且不会连成别的词（NT） |
| `SYNC` | S(0,6) Y(2,5) N(2,3) C(1,1) | `Y` 全板唯一在 (2,5)、`C` 只有四处 → 这是能拿到的最紧一簇 |
| `OTA` | O(5,0) T(4,3) A(4,1) | 一簇 |
| `TIME` | T(1,6) I(2,7) M(0,8) E(1,7) | 3×3 极紧（`M` 只在顶行） |

### 单向性（monotonicity）：可读性的硬约束

左右和上下不可能同时单调，所以只要求**一条轴**严格单调：

- **英文词标签**（NET / SYNC / OTA / TIME）：必须 **列从左到右**（退一步可接受
  "行从上到下"）。方向就是给眼睛的串词线索。反例：`NET` 若排成
  `(9,2)N → (9,1)E → (9,0)T`，虽然也是一条轴单调，但方向是右→左，读出来是 **TEN**。
- **名字拼写**（KLARA）：允许任意方向单调——方向本身就是语义
  （右下 → 左上"升起"）。这也是用户最初的设想。

**算法选字与手选字用同一套标准**：`resolveLabel` 现在是**有约束的穷举搜索**
（列→ 优先、其次 行↓，目标 = 最小跨度 + 最短路径），手写点位则用编辑器里实时
显示的体检结果核对（`单向性 列→ · 跨度 2×3`）。当前全部通过：

| 词 | 点位 | 方向 | 跨度 |
|---|---|---|---|
| `AP` | A(0,7) P(0,9) | 列→ | 0×2 |
| `WIFI` | W(2,1) I(0,3) F(2,6) I(2,7) | 列→ | 2×6 |
| `WAIT` | W(2,1) A(1,4) I(2,7) T(3,9) | 列→ | 2×8 |
| `NET` | N(5,1) E(5,2) T(4,3) | 列→ | 1×2 |
| `SYNC` | S(3,4) Y(2,5) N(3,7) C(1,10) | 列→ | 2×6 |
| `OTA` | O(6,1) T(4,3) A(1,4) | 列→ | 5×3 |
| `TIME` | T(1,6) I(2,7) M(0,8) E(2,9) | 列→ | 2×3 |
| `KLARA` | K(9,10) L(7,6) A(4,1) R(1,5) A(0,5) | 行↑ | 9×9 |

### 动效的速度/方向要跟"这件事的性质"对齐

同一对状态（扫描 vs 连接）用同一套身份标签 + 不同运动，语义就自己分化了：

| 性质 | 运动 | 例子 |
|---|---|---|
| **耗时、可以等** | 慢，且**方向与标签的阅读方向一致**（横向左→右） | 扫描信道 2.4s/轮 |
| **短促、握手** | 快，且用**对角手势**（与开屏同一个家族） | 连接 WiFi 0.75s/轮 |
| **需要确认成功** | 一次性事件（流星/涟漪） | 客户端连入 |
| **不能中断** | 身份常亮 + 缓慢连续扫 | OTA 写入 |

"扫的方向 = 读的方向"这条很实用：`WIFI` 在板上从左到右排列，扫描就横向左→右，
眼睛会把"光在往右走"和"正在依次检查"自动联系起来；若改成纵向扫，动效和标签
就各说各话了。

### 什么时候用标签、什么时候用运动

不是所有状态都适合点名（写词）。判断标准是**这个状态的语义能不能用一个 3~4
字母的名词概括**：

- 能概括 → 用标签词（AP / WIFI / WAIT / SYNC / OTA / NET / TIME）
- 不能，或词在板上排不出可读阵型 → 用**运动**表达（扫描 = 快扫；连接成功 = 流星）

`SCAN` 就是后者：按单向性标准搜索，最紧的摆法也要 9×5（S、C、A、N 的分布太刁钻），
读不出方向。与其硬摆一个认不出的词，不如**复用它所属子系统的标签**：
`WIFI 常亮 + 纵向快扫`。这样既保留了身份（是 WiFi 的事），又用运动说出了
动作（在扫），而且不增加词表——用户只需要认识 WIFI 一次。

### 时序单向性：空间做不到时的回退

如果某个词在板上**根本不存在**任何单轴单调的摆法（字母分布太刁钻），就不再强求
空间顺序，改为**按顺序逐个渐亮渐隐**——用**时间**维持单向性：

```
字母 k 的窗口 = [k·step, k·step + fade + hold + fadeOut]
重叠少量即可，任意时刻只有 1~2 个字母是亮的
```

这样"先 A 后 B"由时间保证，与字母摆在哪无关。触发条件：

- 显式 `mode: "sequence"`
- 或者 `mode: "progress"` 但检测到点位无单向性（编辑器会显示
  "⚠ 空间无单向性 → 已改用时序单向性"）

**为什么这条规则是统一的**：空间单向性和时间单向性表达的是同一件事——"有先后"。
空间能做到就用空间（可以常亮、可以累积，信息量更大）；做不到就用时间，退化成
顺序播放。两者互斥地覆盖了所有情况，不需要第三种方案。

**为什么有些词怎么摆都紧不了**：字母阵是为数字词设计的，`Y`/`M`/`C`/`K` 这类字母
在板上极少（Y 唯一、M 只在顶行、K 唯一）。要更"像字"，只能换词（选一个字母都在
相邻位置的词）——而系统词都不满足。这是媒介的物理限制，不是实现问题。

**② 蛇形走线必须做逆映射。**
面板是蛇形走线（奇数行反向），任何"按行列算距离"的逻辑（风的方向、标签选格、
拼写连线）都必须先把 LED 序号转成**物理行列**。本轮踩过：`ledRC()` 少了
`col = row % 2 ? cols-1-raw : raw` 这一步，导致 `OTA` 解析成 `HIA`、风的方向整行镜像。

**② 错误的语义不要靠标签或颜色区分，靠"还能不能报时"本身区分。**

| 情形 | 表现 | 语义 |
|---|---|---|
| 网络断了，但时间还知道 | **时间照常显示，但暗 50% + 偏暖**，一颗角点缓慢搏动 | "还能用，但有毛病" |
| 时间未知（从未同步成功） | **完全不给时间**，只有 TIME 闪烁 | "我不知道现在几点" |

第一条（降级显示）在实验台里实测非常直观：用户不需要学任何映射，看到"能读出来
但明显发暗的时间"就知道设备在降级工作。这也符合产品逻辑——**断网不该让钟变瞎**。

### 日常读时：星空必须"让路"（默认配置）

运行态的目标是**读时间**，不是欣赏动效。所以默认配置里星空被压到最低：

| 维度 | 运行态 | 其他状态 |
|---|---|---|
| 闪烁 | **完全静止**（`rate: 0`） | 闪烁/风/潮汐 |
| 峰值 | `peakMul: 0.30` → 最亮星码值 ≈ **15** | 满幅 |
| 唯一活动元素 | **planet 暖点** 14s 极慢呼吸（码值 1~7） | — |

这条同时纠正了一个**自相矛盾**：框架里写着"文字 255 > 标签 60~90 > 星场 8~20"，
但运行态原来的星场峰值是 α 0.6（码值 81）——已经跑到"标签"层，和时间文字抢注意力。

为什么敢让星空完全静止：

1. **不动的发光面会被怀疑坏了**这个担心，在运行态不成立——时间文字每分钟换一次词，
   还有换词滴答，本身就是周期性"我在"的信号。
2. 闪烁的预算应该留给**异常与等待**。平时安静，出问题时才有对比——这比一直闪更
   有信息量。
3. planet 保留一个 14s 的极慢呼吸，就足够表达"还活着"，且不会干扰读字。

实验台提供一键 A/B（星场面板的「运行时星空」：静止 / 缓闪 / 闪烁），改的是当前主题
`running` 态的描述符，不是隐藏参数。

### 语言约定："K 是这盏钟的'我'"

`K` 全板只有一个，在 `(9,10)`（右下角）。把它当作设备的第一人称，会得到一组
自然呼应：

- **开屏**：对角扫带从 K 起向左上推进 → "我从这里醒来"
- **有人连入**：涟漪从 K 向外扩散 → "我注意到你了"
- **归零**：按阅读顺序熄灭，最后灭的是 K → "最后是我"
- **标签词**：不与 K 冲突（标签走散落铺开，K 保留给"自身事件"）

这条约定让分散的状态共享一个隐含主角，比每处单独设计更容易被记住。

### 已合并的主题 v3（融合）

取两套之长：语义结构用 v1 的（扫带/涟漪/chase 这些离散动作区分度高），
情绪底色用 v2 的（星场）。

| 状态 | 视觉 | 语义 |
|---|---|---|
| boot | 从**右下 K 起点**的对角扫（550ms）→ KLARA 逐字渐亮并**常亮**成星座 | 自检 + 私人签名 |
| ap_start | **标签 AP** 慢速同步闪 | 热点已就绪 |
| wifi_connecting | **标签 WIFI** 慢速同步闪 | 卡在连 WiFi 这一步 |
| wifi_scanning | **纵向快扫**（0.45s 一轮，连扫几轮） | 在逐条信道找（`SCAN` 排不出可读阵型，故用运动表达） |
| provisioning_wait | 潮汐 + **标签 WAIT** 慢速同步闪 | 轮到你了，不催 |
| provisioning_client | **涟漪从 K(9,10) 扩散** | "有人连上了，从我这里荡开" |
| ntp_syncing | **标签 SYNC 累计点亮 + 四角点当 25% 刻度** | 在同步（不是"加载中"） |
| running | 星场 + 时间文字（最亮层） | 正常 |
| minute_change | 旧字淡出 / 新字淡入 + 四角点滴答 | 换词 |
| ota_download / apply | **同一套进度动效，标签换 OTA** + 刻度；apply 再加背景对角扫表示"写入中" | 在升级 |
| error_network | **时间降级显示**（0.5 亮度、偏暖）+ **NET 慢速点名** | 还能报时，毛病在网络 |
| error_time | 星场极暗 + **TIME 闪烁** | 不知道几点 |
| factory_reset | 星落（**按阅读顺序**熄灭 → 最后熄灭的是 K） | 归零，最后是我 |
| deep_night | 只有星场 | 深夜 |
| apply_config | 对角扫一次（与 boot 呼应） | 保存并重启 |

"校时/OTA 用同一动效、只换标签"是用户提出的关键点，已实现：两者的差异只是
`label.text` 与进度来源，包络与刻度完全一致——用户学到一次"进度语言"即可复用到
所有需要等待的操作。

## 动效阶段：固定清单（固件契约）

状态的**集合**由固件决定，主题只能决定每个状态怎么表现。缺态必须有兜底，
否则一个坏主题可以让"出错"毫无表示。

| id | 触发 | 主题可否省略 |
|---|---|---|
| `boot` | 上电自检 | 否（兜底：全灭） |
| `ap_start` | 起 SoftAP | 可 |
| `wifi_connecting` | STA 连接/重试 | 否 |
| `wifi_scanning` | 扫描信道（配网页请求时按需触发，1~2s） | 可 |
| `provisioning_wait` | 热点已开，等用户 | 可 |
| `provisioning_client` | 有客户端接入（瞬时事件） | 可 |
| `ntp_syncing` | SNTP 等待 | 否 |
| `running` | 正常走时 | **否**（核心） |
| `minute_change` | 换词（瞬时事件，见下） | 可 |
| `ota_download` | OTA 下载（带真实进度） | 可 |
| `ota_apply` | 校验/写入 | 可 |
| `error_network` | WiFi 认证失败/断网重试 | **否**（强制兜底） |
| `error_time` | NTP 失败、时间不可信 | **否**（强制兜底） |
| `factory_reset` | 清 NVS | **否**（强制兜底） |
| `deep_night` | 深夜时段（可选功能） | 可 |
| `apply_config` | 保存配置并重启 | 可 |

## 过渡层：动效之间怎么切换（上一轮缺的那块）

这是框架能力，不属于任何单个状态——因为过渡是**唯一一个两个状态同时存在**的时刻。

```
transition := { dur: ms, curve: "crossfade" | "wipe" }
```

- 状态切换时保存上一帧（114 字节），在 `dur` 内按 `smooth()` 做交叉淡入淡出。
  成本：一个 114 字节缓冲 + 一次线性插值，可忽略。
- **`loading → running` 是这套语言最高光的时刻**：两个状态共享同一片星空，所以
  交叉淡入天然读作"星星聚拢成文字"——不需要写任何新代码，只需要 600~800ms。
- **`minute_change` 也是过渡，不是状态**：旧字 260ms 淡出、新字 260ms 淡入，
  再叠 `tick` 生成器让四角点"滴答"一下。建议固件把它实现成"一次性事件
  （one-shot overlay）"而不是状态，避免和 `running` 抢状态机。
- 反例：`error → running`（恢复）用同一条 crossfade，但要把 `dur` 拉长到
  1.2s 左右——"天慢慢亮回来"，这才是"天空"的语言，而不是 UI 的即时切换。

## 开屏（boot）：两段式

物理约束：面板是 QLOCKTWO 式**固定字母镂空**，所以"显示 KLARA"不是写字，
而是**在这块字母阵里找出这五个字母所在的格子，逐个点亮**：

- `K` 全板只有一个，在 `(9,10)`（底行最右）
- `L` 取离 K 最近的 `(8,7)`；`A` 有两个 `(4,1)` 与 `(1,4)`（散开 6 格）；`R` 取 `(4,5)`

`spell` 的选格规则（为了让散落感像星空而不是写字）：

1. 首字母取"最靠右下"的出现处（K 天生收尾感）
2. 之后每个字母取"离上一格最近"的**未用过**格子 → 连起来像星座连线
3. **同一个字母第二次出现时，要求离该字母上次用的格子 ≥ `spread` 格**
   —— 所以 KLARA 的两个 A 会散开，一在中左、一在偏上，像两颗星

每个字母的包络是"渐亮 → 停留 → 渐隐"，任意时刻只有 1~2 个字母是亮的。

| 段 | 生成器 | 时长 | 目的 |
|---|---|---|---|
| ① 对角快扫 | `band{axis:"diag", period:0.55, peak:0.45}` | 550ms | **功能性自检**：验证 114 颗都能亮。峰值压低（全白 114 颗约 6.8A） |
| ② 名字星座 | `spell{letters:"KLARA", delay:0.40, step:0.38, fade:0.50, hold:0.70, fadeOut:0.55, spread:3, peak:0.95}` | ~3.1s | 品牌/私人化时刻；慢速渐亮渐隐，两个 A 散开 |

合计约 **3.7s**（其中名字段 3.1s）。这是"仪式感 vs 等待"的取舍点：嫌久就压
`step`/`hold`，或只在冷启动（而非每次复位）时播放。

`spell` 是通用生成器，`letters` 可配置；面板上不存在的字母会被跳过。

## 星场算法规格（可直接移植）## 开屏（boot）：两段式

物理约束：面板是 QLOCKTWO 式**固定字母镂空**，所以"显示 KLARA"不是写字，
而是**在这块字母阵里找出这五个字母所在的格子，逐个点亮**：

- `K` 全板只有一个，在 `(9,10)`（底行最右）
- `L` 取 `(8,7)`（离 K 最近），`A` 取 `(4,1)`/`(1,4)`，`R` 取 `(4,5)` …
- 解析规则：第一个字母取"最靠右下"的出现处，其后每个字母取离上一格最近的
  出现处（曼哈顿距离）→ 读起来像在画一条星座的连线

因此 boot 分两段：

| 段 | 生成器 | 时长 | 目的 |
|---|---|---|---|
| ① 对角快扫 | `band{axis:"diag", period:0.55, peak:0.45}` | 550ms | **功能性自检**：验证 114 颗都能亮。峰值压低（不要全白，114 颗全白约 6.8A） |
| ② 名字星座 | `spell{letters:"KLARA", step:0.24, fade:0.14, hold:0.55, persist:0.12, peak:0.95}` | 1.4s | 品牌/私人化时刻；已拼出的字母留 12% 余晖，形成"星座" |

`spell` 是通用生成器，字母串可配置（换人名只改描述符）。面板上不存在的字母会被跳过。

**取舍说明**：纯自检（快扫）不好看，纯名字不好验证硬件。两段加起来 1.95s，
在可接受的等待内同时满足"每颗都验证过"和"这是谁家的钟"。

## 星场算法规格（可直接移植）

```
seed = 20261018                       # 固定 → 每次开机同一片星空
order = 用 mulberry32(seed) 洗牌 [0..109]
n = 32; nBright = round(n * 0.5)      # 用户选定基线：亮星一半
for i in 0..n:
    magScale = i < nBright      ? 1.00..0.85 (线性)
             : i < nBright+13   ? 0.55..0.45
             :                    0.30..0.22
    star[i] = {
        led:    order[i],
        peak:   0.60 * magScale,       # 峰值 α 0.6 → 顶格码值 ~81
        period: 3.6 + (9.5-3.6) * rand(),   # 连续值 → 互不整除
        phase:  rand(),
        tint:   rand()<0.62 ? 近白 : rand()<0.55 ? 冷 : rand()<0.75 ? 暖 : 琥珀,
    }

# 每帧
u    = (t / star.period + star.phase) % 1
env  = sin(pi*u)^4                     # 尖峰：快起慢落，大部分时间接近熄灭
a    = floor + (peak - floor) * env    # floor = 0.006（不归零，避免"死屏"感）
```

选 `sin^4` 而不是对称的 `ease-in-out`：对称曲线会让每颗星"匀速呼吸"，淡入淡出各占
一半时间，实测（实验台对照）读起来是一锅均匀的暗字母；尖峰曲线让每颗星**大部分
时间近乎熄灭、偶尔闪一下**，同时只有 ~14 颗可见，才像真星空。

参考基准：`blog.trav.one` 暗夜页头 = 40 颗星、三档尺寸、`opacity 0.12→0.75`、
周期 2.5–5.5s、外加一颗暖色静止的 `planet`。

## 实验台用法

```bash
python3 tools/anim_lab.py            # http://<本机IP>:8901/
```

- 左侧舞台是「面板视图」，几何照抄 `enclosure/scad/wordclock.scad`
  （pitch 16.58mm / 字高 10.5mm / 格栅壁 1.2mm / 四角光腔 9mm / Allerta Stencil）。
- **相机曝光**只放大预览观感，模拟暗室长曝光，**不改变**导出的 8bit 值。
- `?state=connect&t=2.2&pause=1&exposure=2.6` → 可分享"这一帧"，便于讨论与回归。
- 「导出 golden 帧 CSV」是给固件单测用的：网页算出的 `level` 必须和 Rust 实现逐帧一致。
- 「播放完整状态序列」30 秒过一遍所有状态，用来判断它们是否像一个家族。

## 落地计划

1. `wordclock-core/src/anim.rs`：纯函数 `frame_at(t_ms, state) -> [Level; 114]`，
   no_std、无分配，宿主机单测 + golden CSV 对照。
2. `firmware/app`：调度层 20–30fps（氛围层）/ 按需重绘（文字层：静止时不重发帧）。
3. 帧成本：114×24bit ≈ 3.4ms，20fps 下约占 0.7% 时间。
4. 硬上限：整帧通道和 ≤ 3000/87210（≈ 平均 0.7A），防止将来玩脱。
